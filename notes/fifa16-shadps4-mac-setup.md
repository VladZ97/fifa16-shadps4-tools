Readback-mode finding (2026-10-28 afternoon, side build, Metal HUD via MTL_HUD_ENABLED=1): the Precise readbacks setting is the frame-rate serialiser. Precise: open play 34 FPS, GPU 17.5 ms / frame 29 ms. Relaxed (readbacks_mode 1): open play 45-55 FPS, GPU 10-11 ms / frame 18-22 ms; crowd close-ups 24-28. Plan: log every CPU read fault in Precise mode (SHAD_LOG_READBACKS=1 in Rasterizer::ReadMemory) to separate the one-off kit-build readbacks (needed) from the per-frame ones (the cost), then make a hybrid mode. Drain hunt results (2026-10-28 14:00-14:30, side build, all behind env switches, see ~/fifa_perf/shadps4): every CPU read fault on a GPU-modified 4K page costs DownloadMemory(512 KB window) + scheduler.Finish() = full GPU drain. Logged ~17k per match. Sources and fixes: (1) pipeline cache reading shader binaries / fetch shaders that share pages with GPU-written buffers -> GetParams/ParseFetchShader now read via Memory::TryGetBacking (unprotected alias; SHAD_NO_BACKING_SHADERS=1 reverts): GPU-thread faults 13300 -> 0, open play 34 -> 42-47 FPS, GPU 17.5 -> 11 ms. (2) Eager downloads of linear/small images -> SHAD_READBACK_ALL_ONDEMAND=1 (players still correct). (3) A label page (0x26b7ff000) polled by the game's render thread and read by the CE for its command buffer: dirtied by tiny GPU-side fills/copies (DmaData 8-byte fills, WriteData into a dirty page, GDS copies) -> testing DownloadSmallAsync after tiny fills/copies (+ DownloadMemory early-return must Finish+PopPendingOperations if pages still marked, else infinite fault loop). WaitRegMem backing poll (SHAD_BACKING_POLL=1, now opt-in) did not reduce faults and probably caused a 20 s stall at 8-13 FPS. SHAD_CP_LABEL_WRITES (DMA fills CP-side) did nothing. Diagnostics: SHAD_LOG_READBACKS=1 (+ LOG_EXTRA="Render:info" for autotest) logs READBACK addr/size/gpu_thread and backtraces; SHAD_LOG_GPUWRITES=1 (very verbose), SHAD_WATCH_PAGE=<hex>, SHAD_LOG_IMAGES=1.
